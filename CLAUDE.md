# Інструкції для coding-агента (Claude Code)

Репозиторій курсового проєкту AI Engineering: три частини, кожна - окреме ДЗ. `task1-extraction/` (ДЗ 1) і
`task2-rag/` (ДЗ 2) здано; `task3-agent/` (ДЗ 3) - агент над корпусом ДЗ 2 з власним MCP-сервером. Опис кожної
частини - у її README, результати - у її REPORT.md.

## Як працюємо
- Спілкування з користувачем **українською**, простими словами. Код, коментарі, повідомлення комітів і README - англійською;
  REPORT.md і REFLECTION.md - українською.
- Великий крок ДЗ спершу пояснити: про що він, які зміни і навіщо. Далі робити **по одному підкроку** і чекати «так»
  перед наступним. Після підкроку - короткий звіт: що зроблено, навіщо, які перевірки, що не зроблено.
- **Коміти прямо в `main`**, одним комітом на підкрок; у повідомленні - що змінено, чому і результати прогонів.
  **Пуш робить користувач сам** (`git push origin main`), агент не пушить.
- **Прогін на моделі коштує грошей і виконується лише з дозволу користувача** у цій розмові (вказати, що саме і скільки
  коштує). Тести без моделі запускати завжди.
- Не пропускати перевірку на справжній моделі там, де змінюється поведінка агента: тести без мережі не ловлять, що модель
  робить насправді (так знайдено більшість вад, див. `task3-agent/REPORT.md`).
- Провали, які не виправляємо, **чесно лишати** в результатах і звіті; перевірку не послаблювати, щоб вона «пройшла».
- Важливе для безпеки робити в **коді**, а не лише в промпті (підтвердження людиною, права доступу, захист від ін'єкції,
  квитанція змін): промпт модель може не виконати.

## ДЗ 3 (`task3-agent/`)
Налаштування один раз (Python 3.11):

    cd task3-agent
    python3.11 -m venv .venv
    .venv/bin/pip install -r requirements.txt -r ../task2-rag/requirements.txt
    cd ../task2-rag && ../task3-agent/.venv/bin/python -m rag.retrieval.build && cd ../task3-agent   # індекс Chroma

Команди (з `task3-agent/`):

    for t in tests/test_*.py; do .venv/bin/python $t | tail -1; done   # усі тести без моделі; мають бути "all checks passed"
    .venv/bin/python main.py "питання"                                  # агент на моделі (потрібен ключ)
    .venv/bin/python -m evals.run --repeat 3 --only a01,h03             # частина тестових сценаріїв на моделі
    .venv/bin/python -m evals.run --repeat 3                            # усі сценарії, ~$0.10, лише з дозволу
    .venv/bin/python evals/make_tasks.py                                # після зміни сценаріїв: перегенерувати tasks.jsonl

Правила коду ДЗ 3:
- **Промпти й описи інструментів - версіоновані файли** (`prompts/system_vN.md`, `prompts/tools/*.yaml`, `prompts/memory_vN.md`).
  Опублікований текст не правити: нова версія + запис у `prompts/CHANGELOG.md` (що змінено і який прогін це показав),
  версія в `config.yaml` або в yaml-файлі.
- **Тестові сценарії** (так їх називаємо в документах; у коді - tasks) редагуються в `evals/make_tasks.py`, не в
  `tasks.jsonl`. Прогони eval (`evals/runs/<дата>/`) комітяться разом з trace; старі прогони не змінювати.
- Корпус і пошук ДЗ 2 не змінювати: додаткові документи ДЗ 3 - у `task3-agent/corpus_extra/`.
- Назви: **TMS** (test management system, база тест-кейсів `data/tms.db`), **тестовий сценарій**, категорія **writes**
  (створення тест-кейсу).
- Кожна зміна поведінки - з тестом без моделі в `tests/`.

## Ніколи не комітити
`.env` (ключ `OPENROUTER_API_KEY` - лише там, не в коді і не в чаті), `.venv/`, `.claude/settings.local.json`,
`task3-agent/data/` (TMS, пам'ять, feedback), `task3-agent/traces/`, індекс `task2-rag/rag/data/chroma/`.
